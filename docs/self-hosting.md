# Свой сервер синхронизации

Just работает без сервера: задачи хранятся на устройстве. Чтобы синхронизировать компьютер и телефон, поставьте свой сервер.

## Что нужно

- Linux-сервер с Debian или Ubuntu, доступный из интернета (подойдёт самый дешёвый VPS).
- Один открытый TCP-порт. Домен не нужен.

## Установка

```bash
curl -fsSL https://raw.githubusercontent.com/me0wdes/just/main/server/install.sh | sudo bash
```

Скрипт ставит Node.js 24, запускает сервер как службу `just-sync`, создаёт ключ доступа и включает ежедневную резервную копию всех баз (14 дней, `/var/lib/just-sync/backups`). В конце он печатает строку подключения `just1:…` и QR-код.

Just отвечает по HTTPS сам, прямо по IP-адресу сервера: на порту 443, а если он занят (сайтом, VPN, панелью), то на первом свободном из 8443, 2053, 2083, 2087, 2096, 9443, 10443. Сертификат сервер выпускает себе сам, его отпечаток лежит в строке подключения, и приложение доверяет только ему. Поэтому не нужны ни домен, ни Let's Encrypt, ни свободные 80 и 443, и не мешает блокировка сервисов вроде sslip.io. Свой порт: `sudo JUST_PORT=12345 bash install.sh`.

Если у хостинга есть брандмауэр в панели управления, откройте в нём порт, который назвал установщик.

### Со своим доменом

Можно и с доменом (его A-запись должна указывать на сервер), тогда нужны порты 80 и 443. Just встаёт за nginx или Apache, если они уже есть, или ставит Caddy, и получает сертификат Let's Encrypt:

```bash
curl -fsSL https://raw.githubusercontent.com/me0wdes/just/main/server/install.sh | sudo JUST_DOMAIN=tasks.example.com bash
```

Серверы, поставленные до прямого режима, остаются с доменом. Перевести такой сервер на прямой режим (строка подключения сменится, подключите устройства заново):

```bash
curl -fsSL https://raw.githubusercontent.com/me0wdes/just/main/server/install.sh | sudo JUST_MODE=direct bash
```

## Подключение

В Just: **Настройки → Хранение данных → Свой сервер**, вставьте строку и нажмите «Подключить». Повторите на каждом устройстве. На втором устройстве выберите «Объединить», чтобы задачи с обоих устройств сложились вместе.

Строка содержит ключ доступа: храните её как пароль. Показать её снова: `sudo just-sync owner`.

## Несколько человек на одном сервере

Один сервер можно поделить с семьёй или друзьями. У каждого человека свой ключ и своя база, поэтому чужие задачи никто не видит, даже случайно.

Добавить человека (имя латиницей, например `mama`):

```bash
sudo just-sync add mama
```

Команда напечатает строку подключения и QR-код для этого человека. Передайте строку лично: кто её знает, тот видит задачи. Человек подключается так же, как вы: **Настройки → Хранение данных → Свой сервер**.

| Что нужно | Команда |
|---|---|
| Кто есть на сервере | `sudo just-sync list` |
| Человек потерял строку или её кто-то увидел | `sudo just-sync add mama` ещё раз: будет новый ключ, старый перестанет работать, задачи останутся |
| Закрыть доступ | `sudo just-sync remove mama`, задачи остаются в `/var/lib/just-sync/users/mama` |
| Удалить задачи человека насовсем | после `remove`: `sudo rm -r /var/lib/just-sync/users/mama` |

Что важно знать:

- Владелец сервера технически может прочитать любую базу: файлы лежат на диске без шифрования. Скажите об этом людям, которых добавляете.
- Ключ хранится на сервере только в виде хеша, поэтому показать строку человека ещё раз нельзя. Если строка потерялась, выдайте новую через `add`.
- Регистрации и паролей нет: людей добавляет только владелец сервера.

## Обслуживание

- Состояние: `systemctl status just-sync`
- Журнал: `journalctl -u just-sync`
- Обновления: сервер сам проверяет новую версию каждую ночь (таймер `just-sync-update`) и перезапускается, только если она вышла. Обновить сразу: запустить установщик ещё раз
- Восстановить копию: `systemctl stop just-sync`, заменить базу нужным файлом из `backups`, `systemctl start just-sync`. Ваша база: `/var/lib/just-sync/sync.sqlite`, копии `sync-<дата>.sqlite`. База человека: `/var/lib/just-sync/users/<имя>/sync.sqlite`, копии `user-<имя>-<дата>.sqlite`
