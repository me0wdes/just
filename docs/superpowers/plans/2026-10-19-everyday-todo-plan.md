# Everyday Todo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Создать личное приложение День для Windows и Android с удобным списком, локальным сохранением, синхронизацией, напоминаниями и звуковым откликом.

**Architecture:** Flutter клиент хранит данные и очередь операций в SQLite. Независимый сервис Node.js и SQLite принимает операции, выдаёт канонические изменения и устраняет дубли. Системные уведомления, безопасное хранение ключа и звук подключаются после проверки локального клиента и протокола.

**Tech Stack:** Flutter stable, Dart, Drift NativeDatabase, Node.js 24, node:sqlite, flutter_local_notifications, flutter_secure_storage, audioplayers, timezone, uuid; ChangeNotifier для интерфейса.

**Spec:** [Согласованная спецификация](../specs/2026-10-18-everyday-todo-design.md).

## Global Constraints

- «личное использование, Windows и Android, синхронизация, меньше страниц, плавность и звуковой отклик».
- «интерфейс на русском, светлая и тёмная темы»; один личный набор данных на сервис.
- «Название после удаления внешних пробелов — от 1 до 500 символов, заметка — до 10000».
- «Даты без времени хранятся как YYYY-MM-DD»; reminderAtUtc отдельно от dueDate и с reminderTimezone.
- «POST /sync принимает курсор и до 100 операций»; «Максимальный размер запроса — 256 КиБ».
- «пока приложение активно, дополнительно выполняется обмен каждые 15 секунд»; повтор ошибки от 2 до 60 секунд.
- «Высота обычной строки около 60–72 логических пикселей, интерактивная область не меньше 48».
- «При ширине от 900 логических пикселей слева показывается панель списков шириной около 216»; «Минимальное рабочее окно 760 × 560».
- «Клавиатура: Enter сохраняет задачу, Escape закрывает панель или поиск, Ctrl+N фокусирует добавление, Ctrl+F открывает поиск».
- «Галочка заполняется примерно за 140 мс»; зачёркивание 160–180 мс, перестройка 180–220 мс, панель 200–240 мс.
- «Короткий локальный звук выполнения длится приблизительно 80–140 мс»; удалённое обновление звука не вызывает.
- «Рабочее соединение только HTTPS с обычной проверкой сертификата»; HTTP только явно включённый loopback для разработки.
- Flutter и Android SDK пока не обнаружены. Настройка инструментария входит в клиентский этап; лицензионные соглашения не принимаются молча.
- Установка на телефон, проверка системных уведомлений и VPN являются отдельными проверками. Нельзя заменять их прохождением unit тестов.
- До начала реализации получить просмотр этого плана и выбор способа исполнения. Рекомендуется Native: один исполнитель в этом чате, так как клиент, очередь и сервис тесно связаны.

## Общие контракты

Имена JSON полей camelCase. Идентификаторы — UUID; для встроенного списка Входящие зарезервирован `00000000-0000-4000-8000-000000000001`. Удаления передаются tombstone, без исчезновения записи из журнала. Произвольные поля отклоняются. Клиентские даты не используются для порядка конфликтующих правок.

```text
SyncRequest = {protocolVersion:1, deviceId:UUID, cursor:int>=0, operations:Operation[]}
Operation = {operationId:UUID, localSequence:int>=1, entityType:"list"|"task"|"rule",
             entityId:UUID, kind:"create"|"patch"|"delete"|"restore"|"complete"|"undoComplete",
             changes:object, dependsOn:UUID[], createdAt:UTCString}
SyncResponse = {protocolVersion:1, workspaceId:UUID,
                acknowledgements:Ack[], changes:EntityChange[], nextCursor:int, hasMore:bool}
Ack = {operationId:UUID, status:"applied"|"duplicate"|"rejected", code?:string,
       effect?:{completionId:UUID, successorId:UUID|null}}
EntityChange = {entityType, entityId:UUID, revision:int, value:object}
```

Обычные patch поля задачи: title, note, listId, dueDate, reminderAtUtc, reminderTimezone, plannedForDate, position, recurrenceRuleId. completedAt, successorId и удаление меняются только соответствующими командами. Позиции начинаются с 1024 и увеличиваются с шагом 1024; одинаковые позиции сравниваются по id. Еженедельные дни — ISO 1…7; месячный день — 1…31. Все повторные вычисления сверяются с общими fixtures.

Транзакция сервера обрабатывает только первые принятые переходы завершения. Следующий экземпляр UUIDv5 от ruleId и occurrenceDate. Дата его создания определяется каноническим первым завершением; позднее завершение не пересчитывает её. Операция complete содержит проверенную календарную completionDate в зоне правила. Сервер возвращает канонический completionId даже второму завершившему клиенту. Для предварительного офлайн потомка клиент использует локальную таблицу связи и удерживает его дальнейшие операции до разрешения канонического id.

В ответ включаются актуальные состояния затронутых сущностей после cursor в порядке ревизии, максимум 500 событий за страницу. nextCursor — ревизия последнего реально выданного события, а не текущая максимальная ревизия сервера, если выдача неполная. Применение входящих изменений не закрывает ещё не подтверждённые локальные операции.

Ошибки: 401 ключ, 413 размер, 400 формат, 409 несовместимая версия или перепутанный workspace. Ошибка отдельной операции имеет Ack rejected и конкретный code, не блокирует независимые операции. Блокируются только операции с неразрешённой зависимостью. Ошибки сети оставляют очередь нетронутой.

Для подтверждённого импорта операция restore может содержать `changes.snapshot`: полный валидированный снимок одной сущности, включая историческое completedAt и связи completionId/successorId. Она восстанавливает отсутствующую, удалённую или совпадающую по id запись без запуска побочных эффектов complete. Импорт завершённой истории не создаёт новые будущие экземпляры. Служебную серверную revision и подтверждения операций из файла не импортировать. Для отмены обычного удаления restore без snapshot использует сохранённое состояние tombstone.

## Критерий завершения всего проекта

Все задачи A1–C4 выполнены, воспроизводимые автоматические проверки проходят, Windows артефакт и Android APK собраны. В verification.md явно перечислены результаты на настоящих устройствах и с VPN. Пока нет доступного сервера либо подключённого телефона, соответствующие строки остаются непроверенными и продукт не называется полностью готовым.

Внешний сервер и Android телефон могут потребовать пользовательского участия в момент подключения. До этого выполняются все независимые локальные работы и готовятся конкретные сборки; вопрос о доступе не задаётся заранее вместо реализации.
