# Личный планировщик День для Windows и Android

Дата: 18 октября 2026 года. Статус: согласовано пользователем 19 октября 2026 года. «День» — рабочее название, которое можно заменить без изменения архитектуры.

## Зачем приложение

Пользователю в целом подходит функциональность Microsoft To Do, но мешают лишние страницы, визуальный характер и недоступность на компьютере при работе с VPN. Нужен личный повседневный планировщик на компьютере и Android телефоне: удобный список, плавный отклик, звуки и синхронизация.

Приложение должно сохранять каждое действие на устройстве и оставаться полезным без сети. При появлении связи изменения передаются на второе устройство. Недоступность сервиса синхронизации не блокирует просмотр, добавление и выполнение задач.

## Основания и принятые значения по умолчанию

Подтверждено пользователем: личное использование, Windows и Android, синхронизация, меньше страниц, плавность и звуковой отклик, использование локальной библиотеки дизайнов. Пользователь согласился с направлением: один главный экран, Сегодня, Все, свои списки и редактирование в панели.

Для первой версии приняты следующие значения: интерфейс на русском, светлая и тёмная темы, обычные задачи со сроками, напоминаниями и повторами; один личный набор данных. Регистрации для других людей, совместного редактирования, платных тарифов и административного интерфейса нет. Сроки и повторы работают по локальному календарю пользователя; исходная зона при первом запуске определяется устройством, в текущем контексте — Europe/Moscow.

## Результат первой версии

Пользователь получает Windows приложение, Android APK и инструкцию установки и подключения одного личного сервиса синхронизации. Сначала проверяется работа локального приложения, затем обмен двух независимых клиентов с локальным сервисом, затем реальная связь компьютера и телефона через доступный HTTPS адрес.

Полноценная синхронизация через интернет считается готовой только после размещения сервиса и проверки с VPN пользователя. Локальная демонстрация или сервер на 127.0.0.1 не заменяют эту проверку. Хостинг не покупается и никакой существующий сервер не меняется на этапе проектирования.

## Подход и альтернативы

Выбран Flutter: единый клиент для Windows и Android, контроль над композицией, движением и звуком. Локальные данные хранятся в SQLite через Drift. Сервис синхронизации — небольшой Node.js процесс с SQLite и одним личным набором данных; его HTTPS адрес задаётся в настройках подключения.

Рассмотрены альтернативы:

| Подход | Польза | Цена для этой задачи |
| --- | --- | --- |
| Flutter и SQLite | Общая логика и оформление двух платформ, нативные сборки | Требуется подготовка Flutter и Android SDK, отдельная проверка уведомлений. |
| Веб приложение с установкой PWA | Быстрое распространение и просмотр через браузер | Системные напоминания и работа закрытого приложения сильнее зависят от браузера. |
| Два отдельных нативных клиента | Максимальный контроль платформенных интеграций | Две реализации интерфейса и больше работы по их согласованию. |

На старте достаточно Flutter ChangeNotifier и прямой передачи зависимостей. Дополнительный фреймворк состояния, универсальный конструктор экранов и плагины для будущих платформ не нужны.

## Главный экран

### Телефон

Один рабочий экран: заголовок и дата, переключатели Сегодня и Все, выбранный список, строки задач и всегда доступное добавление внизу. Свои списки открываются из компактной панели; отдельного полноэкранного раздела на каждую служебную функцию нет. Настройки — небольшая панель с понятными группами.

Строка задачи содержит круглую отметку слева, название, необязательные метки срока и повтора. Заметка доступна в подробностях. Высота обычной строки около 60–72 логических пикселей, интерактивная область не меньше 48. Для длинного названия строка увеличивается, обрезания единственного важного текста нет.

Добавление: ввод названия → подтверждение клавиатурой или кнопкой → новая задача сразу в выбранном списке. Дата и напоминание доступны рядом, но не обязательны для сохранения. Открытие задачи показывает панель подробностей поверх списка, сохраняя положение прокрутки.

### Windows

При ширине от 900 логических пикселей слева показывается панель списков шириной около 216, в центре — задачи. При достаточной ширине подробности открываются справа; в более узком окне — поверх списка. Минимальное рабочее окно 760 × 560, без горизонтальной прокрутки. На широком экране строка текста ограничена разумной шириной, свободное место не растягивает названия.

Клавиатура: Enter сохраняет задачу, Escape закрывает панель или поиск, Ctrl+N фокусирует добавление, Ctrl+F открывает поиск. Tab проходит по видимым действиям, фокус всегда заметен. Размер текста и системное масштабирование учитываются отдельно от размеров окна.

## Визуальный характер

Используются выбранные оригиналы из `docs/references`: REF-0547 для структуры, REF-0537 для мягких цветов, REF-0819 для эмоционального отклика и REF-0559 для различимости в тёмной теме. Полная библиотека не копируется внутрь приложения.

Светлая основа: тёплый почти белый фон, графитовый текст, небольшие шалфейные и лавандовые акценты, мягкий жёлтый для важных состояний. Тёмная тема: глубокий графитовый фон и более светлые поверхности; смысл меток остаётся тем же. Цвет не используется как единственный признак выполнения, ошибки или активного раздела.

Для первого прототипа используется системный читаемый sans serif с кириллицей. Название задачи 16, вторичная информация 12–13, заголовок 26–30 логических пикселей. Окончательные цвета проверяются по реальному контрасту текста. Радиусы поверхностей 16–20; у маленьких элементов — меньше. Тени сдержанные, без постоянного размытия всех поверхностей.

Небольшой нейтральный персонаж появляется в пустом списке и при завершении всех дел на сегодня. Он не занимает основную рабочую область и не превращает работу со списком в обязательную игровую механику.

## Движение и звук

Выполнение сразу фиксируется локально. Галочка заполняется примерно за 140 мс, зачёркивание и изменение насыщенности — за 160–180 мс, перестройка списка — за 180–220 мс. Панель подробностей открывается за 200–240 мс. Новое действие может прервать предыдущую анимацию; задержки сохранения ради красивого перехода нет.

При уменьшении движения в системе переходы заменяются коротким изменением прозрачности либо отключаются. Список не проигрывает вступительные анимации заново при каждом удалённом обновлении.

Короткий локальный звук выполнения длится приблизительно 80–140 мс; откат может иметь отдельный более тихий звук. Звук воспроизводится только на явное действие пользователя на текущем устройстве. Полученная с другого устройства отметка не вызывает звука. Звук и вибрация отключаются отдельно; системный беззвучный режим и фокусировка учитываются. Системный звук напоминания отделён от интерфейсного звука выполнения.

## Модель данных

Клиентские идентификаторы UUID создаются до сети. Данные приложения и очередь операций хранятся в локальной БД транзакционно.

| Сущность | Поля |
| --- | --- |
| Список | id, имя, цвет, порядок, удалён, серверная ревизия. |
| Задача | id, listId, название, заметка, dueDate, reminderAtUtc, reminderTimezone, plannedForDate, completedAt, порядок, recurrenceRuleId, occurrenceDate, удалена, серверная ревизия. |
| Правило повтора | id, вид daily/weekly/monthly, выбранные дни недели либо день месяца, часовой пояс, время напоминания при наличии, активно. |
| Операция | operationId, deviceId, локальный номер очереди, entityId, вид операции, только изменённые поля, время локального создания для диагностики. |
| Состояние синхронизации | workspaceId, deviceId, последний применённый серверный курсор, время успешного обмена. |
| Настройки устройства | тема, звуки, громкость, вибрация и разрешения уведомлений. |

Название после удаления внешних пробелов — от 1 до 500 символов, заметка — до 10000. Даты без времени хранятся как YYYY-MM-DD. Момент напоминания хранится в UTC с указанной зоной для редактирования. Изменение часового пояса устройства не сдвигает молча уже установленное напоминание.

Порядок — целые позиции с промежутками; при совпадении используется id как стабильное вторичное сравнение. Внутри Сегодня сначала показаны просроченные, затем сегодняшние и вручную запланированные; ручной порядок применяется внутри соответствующей группы.

## Повторы и отмена

Завершение повторяющейся задачи и создание следующего экземпляра выполняются одной логической операцией. Следующая дата — первое подходящее число строго после более позднего из текущего срока и локальной даты завершения. Для ежемесячного повтора день 29–31 при необходимости ограничивается последним днём месяца. Невыполненная задача не порождает бесконечную пачку пропущенных экземпляров.

Идентификатор следующего экземпляра детерминирован по id правила и occurrenceDate. Повторное получение или отправка одной операции не создаёт дубликат. Два офлайн завершения одного экземпляра создают один следующий: сервер применяет только первый переход текущего экземпляра из незавершённого в завершённый, фиксирует канонический completionId и вычисленную следующую дату. Поздняя попытка завершить уже завершённый экземпляр возвращает эту же каноническую связь, даже если клиент выполнял его в другой календарный день.

Офлайн клиент может сразу показать предварительный следующий экземпляр, привязанный к своей операции завершения. Он не отправляет его как отдельную create операцию. При подтверждении клиент заменяет предварительный результат каноническим; правки предварительного потомка ждут разрешения этой связи и затем адресуются каноническому id. Операция отмены ссылается на канонический completionId: снимает отметку и удаляет созданного ею потомка только если тот не был отдельно изменён; в ином случае приложение объясняет, что следующий экземпляр уже изменён, и даёт открыть его.

Удаление задачи скрывает её сразу, но до нажатия Отменить доступна краткая панель восстановления. Снятие задачи с плана Сегодня не удаляет саму задачу. При удалении пользовательского списка его задачи перемещаются во Входящие. Запоздалое изменение с удалённым listId также попадает во Входящие и не теряется.

## Синхронизация

### Подключение

Один личный набор данных обслуживает один небольшой сервис. В настройках пользователь один раз вводит HTTPS адрес и личный ключ подключения на каждом устройстве. Сервис создаёт криптографически случайный ключ не менее 256 бит; ключ не зашивается в бинарники и не попадает в Git или журналы. На клиенте он хранится через системное защищённое хранилище.

В первом релизе достаточно ручного переноса адреса и ключа; QR код не является обязательной зависимостью. Пользователь может работать локально до подключения. Переключение на другой набор данных сохраняет локальную резервную копию и требует явного выбора: объединить локальные данные с новым набором или открыть его отдельно. Молчаливого обнуления БД нет.

### Обмен

POST /sync принимает курсор и до 100 операций. Ответ возвращает подтверждения operationId, канонические изменённые сущности и следующий курсор. Большие входящие изменения выдаются страницами с признаком продолжения. Максимальный размер запроса — 256 КиБ; очередь разбивается по числу и размеру операций.

Каждое локальное действие и соответствующая операция записываются одной транзакцией. Успешный HTTP ответ сам по себе не удаляет всю очередь: удаляются только явно подтверждённые operationId. Подтверждения, входящие изменения и курсор применяются одной локальной транзакцией. Неподтверждённые локальные изменения накладываются на пришедшее каноническое состояние, поэтому обмен не стирает несохранённый ввод.

Сервис хранит журнал обработанных operationId и монотонную ревизию. Повторная отправка уже принятой операции возвращает прежнее подтверждение и не применяет её повторно. Локальные часы не решают конфликты. Разные обычные поля одной задачи объединяются; для одного поля побеждает последняя принятая сервером операция. Завершение, отмена завершения и генерация следующего повтора обрабатываются отдельными переходами состояния, описанными выше. Удаление является отдельным состоянием и не отменяется запоздалым обычным редактированием; восстановление требует явной restore операции.

Порядок операций одного устройства сохраняется, включая создание списка до создания его задач. Зависимые операции не отправляются раньше подтверждения необходимой сущности. Постоянная ошибка валидации помечает конкретную запись очереди как требующую исправления и показывает причину пользователю; она не вызывает бесконечную сетевую пересылку и не блокирует независимые задачи. Для обновления версии протокола сервис возвращает отдельный понятный код ошибки.

Сведения об удалениях и обработанных операциях сохраняются без автоматического истечения для этого небольшого личного набора. Это позволяет телефону вернуться после долгого офлайна без восстановления удалённых задач. Серверная транзакция атомарно меняет сущность, ревизию и подтверждение операции.

### Когда происходит обмен

При запуске, возврате в приложение, ручном обновлении и после локальных правок. Пока приложение активно, дополнительно выполняется обмен каждые 15 секунд. Один экземпляр синхронизации работает в каждый момент, накопленные изменения подхватываются следующим проходом.

При сетевой ошибке локальная работа продолжается. Повтор с паузой от 2 до 60 секунд с небольшой случайной добавкой; при возврате в приложение попытка выполняется сразу. Показаны спокойные состояния Сохранено на устройстве, Синхронизировано и Не удалось подключиться. Неверный ключ требует исправления подключения, а не бесконечной частой отправки.

Фоновый обмен при полностью закрытом приложении не обещается в первой версии. На Android он зависит от ограничений ОС. Локальные системные напоминания планируются заранее и работают по последнему известному устройству состоянию задач. Удалённая правка не может отменить уведомление на устройстве, которое ещё не синхронизировалось.

## Локальное хранение и резервные копии

SQLite через Drift NativeDatabase работает вне UI isolate, чтобы дисковые операции не мешали прокрутке. Схема имеет версии и проверяемые миграции. Пользовательские данные располагаются в каталоге приложения, независимо от папки установки и исходного кода.

JSON экспорт содержит версию формата, списки, задачи и правила. Личный ключ и настройки безопасности не экспортируются. Импорт проходит проверку формата и предварительно показывает количество новых и совпадающих записей; подтверждённый импорт транзакционно создаёт необходимые операции синхронизации. Дубли определяются по id, без слепого создания копий. Перед изменением сохраняется локальная резервная копия.

Сервис резервирует SQLite штатным backup API. Копирование только основного файла при активном WAL не считается корректной резервной копией.

## Напоминания

Используется flutter_local_notifications с отдельной проверкой Windows и Android. На Android приложение запрашивает право на уведомления в момент установки первого напоминания. Если точное расписание недоступно, пользователь получает понятный статус; интерфейс не утверждает, что точное напоминание установлено. После перезагрузки сохранённые напоминания восстанавливаются предусмотренным платформенным механизмом.

На Windows надёжное управление уже показанными уведомлениями требует package identity; итоговая проверка выполняется для установленного MSIX, а не только распакованного EXE. Поддержка повторяющихся уведомлений не предполагается из API periodicallyShow: планируется отдельное одноразовое напоминание текущего экземпляра. Следующий экземпляр получает своё расписание после выполнения и синхронизации.

Каждому экземпляру соответствует устойчивый notification id. Изменение времени отменяет старое расписание и устанавливает новое; завершение и удаление отменяют локальное уведомление. Нажатие открывает соответствующую задачу. Отключённые системные уведомления показываются как отключённые, без потери установленного пользователем времени.

## Границы компонентов

| Компонент | Ответственность |
| --- | --- |
| domain | Модели задач, даты, правила повторов и допустимые операции. |
| data | SQLite, миграции, репозитории, атомарная очередь изменений. |
| sync | HTTP обмен, подтверждения, курсоры, повторы и объединение состояния. |
| platform | Уведомления, защищённый ключ, звук и вибрация. |
| ui | Главный список, панель задачи, списки, настройки и визуальная система. |
| server | Аутентификация одного набора данных, валидация операций, журнал ревизий и SQLite. |

Виджеты не выполняют SQL и не управляют повторными HTTP запросами. Сервис не зависит от Flutter. Общий протокол описывается JSON примерами и проверяется интеграционно между независимыми клиентами.

## Защита данных

Рабочее соединение только HTTPS с обычной проверкой сертификата. HTTP допускается только в явно включённой локальной среде разработки на loopback; выпуск не содержит отключения проверки TLS. Сервис принимает только известные операции и поля, ограничивает размеры и не пишет содержимое задач и ключи в логи.

Локальная БД содержит обычные данные приложения; отдельное шифрование всей базы в первой версии не заявляется. Приватный ключ защищён системным хранилищем. Сервис размещается под HTTPS прокси, из интернета доступен только необходимый endpoint. Никакой поиск доступности с реальными задачами через сторонние проверки не выполняется: для связи используются пустые тестовые данные.

## Проверки готовности

### Поведение

- Сохранённые задачи переживают закрытие приложения и перезапуск устройства.
- Добавление, изменение и выполнение работают при отключённой сети.
- После восстановления связи два клиента получают одинаковые списки и состояния без ручного экспорта.
- Повторная отправка операции, потерянный ответ и перезапуск во время обмена не создают дубли.
- Параллельные правки разных полей сохраняются; правило для одного поля воспроизводимо.
- Удалённая задача не воскресает после подключения давно офлайн устройства.
- Повторяющаяся задача создаёт ровно один следующий экземпляр, включая одновременное выполнение на двух устройствах.
- Сохраняются правило месяца для 29–31 числа, часовой пояс и случаи перехода даты.
- Неверный ключ и недоступный сервер не блокируют локальные действия.

### Интерфейс

- Телефон шириной 360 и 412, Windows окна 760, 1024 и 1440 логических пикселей.
- Длинные русские названия, пустое состояние, 1000 задач, увеличенный текст и клавиатура телефона.
- Добавление не требует открытия формы с обязательными вторичными полями.
- Фокус и основные действия работают с клавиатуры; элементы доступны семантически.
- Уменьшение движения, отключение звука и получение удалённого выполнения не вызывают лишнего отклика.

### Платформы

- flutter analyze и тесты доменной логики, SQLite и синхронизации.
- Windows release сборка и установка пакета, проверка уведомления при закрытом приложении.
- Android APK на реальном телефоне: разрешения, перезагрузка, уведомление и локальное хранение.
- Обмен Windows ↔ Android с VPN включённым и выключенным на обоих устройствах, временный офлайн и возврат сети.

Нативная сборка, доступность сервера, установка на телефон и реальные уведомления отмечаются отдельно. Отсутствующая проверка не заменяется сообщением об общей готовности.

## Окружение разработки

Проверено 18 октября 2026 года: Windows рабочая машина, Node.js 24.19.0, Git, .NET SDK 10.0.400, Visual Studio Community 2022 с Desktop development with C++ и VC tools x64/x86. Свободное место на диске C около 565 ГБ.

Flutter и Dart не найдены в PATH; стандартные каталоги Flutter и Android SDK отсутствуют. Перед реализацией клиентских сборок устанавливается стабильный Flutter SDK в отдельную папку инструментария, подготавливаются Android SDK и JDK, затем проверяется flutter doctor. Установка и принятие лицензий инструментов не объявляются выполненными без фактической проверки.

## Технические источники

Поддержка Windows и Android проверена по [таблице платформ Flutter](https://docs.flutter.dev/reference/supported-platforms). Требования к Windows сборке — в [официальной инструкции Flutter](https://docs.flutter.dev/platform-integration/windows/setup).

Drift документирует NativeDatabase для Android и Windows и работу вне UI isolate в [описании нативных платформ](https://drift.simonbinder.eu/platforms/vm/). Уведомления и ограничения Windows описаны в [flutter_local_notifications](https://pub.dev/packages/flutter_local_notifications) и [его Windows реализации](https://pub.dev/packages/flutter_local_notifications_windows).

Для защищённого хранения ключа рассматривается [flutter_secure_storage](https://pub.dev/packages/flutter_secure_storage); для воспроизведения встроенного звука — [audioplayers](https://pub.dev/packages/audioplayers). Конкретные совместимые версии зависимостей фиксируются lock файлами при реализации и повторно проверяются сборкой.
