# День: протокол синхронизации v1

POST `/sync`, `Authorization: Bearer <key>`, JSON UTF-8. Максимум 262144 байта и 100 операций. Форматы и поля описаны в [общем плане](../docs/superpowers/plans/2026-10-19-everyday-todo-plan.md).

Envelope проверяется целиком; отдельные операции получают durable acknowledgement applied/duplicate/rejected. Повтор operationId не выполняет операцию повторно. Изменения выдаются по возрастанию серверной ревизии, до 500 на страницу и до 8 МиБ сериализованных изменений. Клиент допускает ответ до 16 МиБ, оставляя запас для подтверждений. Cursor относится к последней выданной записи. Клиент сохраняет canonical state и оставшиеся локальные операции атомарно.

Inbox UUID: `00000000-0000-4000-8000-000000000001`.

Срок задачи — `dueDate` (дата) и необязательное `dueTime` (`HH:MM`, местное время); без `dueTime` срок на весь день. Следующее повторение получает то же `dueTime`. Списки задачи — поле `listIds`: массив до 50 уникальных UUID списков, работает как метки (0, 1 или несколько). Пустой массив означает «Без списка». У списка необязательное поле `icon` — ключ иконки (латиница, до 20 букв, например `home`); без него показывается стопка. Если `listIds` у записи нет (старые клиенты), задача считается в списке `listId`, а Inbox означает «Без списка». Сервер отбрасывает ссылки на удалённые списки и при удалении списка убирает его id из `listIds` всех задач. Полевая правка не заменяет остальные поля; delete оставляет tombstone; restore — явный переход. Время клиента не используется для порядка конфликтов. Первое завершение повторяющейся задачи задаёт canonical completionId и successorId. Undo ссылается на этот completionId.

HTTP: 400 неверная форма/JSON, 401 ключ, 409 версия/workspace, 413 размер, 500 внутренняя ошибка без содержимого запроса. Ошибки отдельной операции возвращаются в HTTP 200 как rejected с code.

Подключённые обмены содержат `expectedWorkspaceId` (UUID): сервер сравнивает его со своим workspaceId до транзакции и отклоняет несовпадение с HTTP 409 без изменения задач или подтверждений. Клиент с ещё неизвестным пространством сначала посылает пустой запрос, сохраняет идентичность, затем отправляет очередь с этим полем. Проверка подключения также не отправляет операций.

Канонический `successorId: null` означает отсутствие следующего повтора. Если пользователь успел изменить локально предсказанного потомка, клиент сохраняет его и изменённых потомков отдельными обычными делами с новыми id. Отклонённые операции остаются видимыми как конфликт до явного выбора версии; перед выбором создаётся JSON копия. Повторный опрос не переводит неразрешённую очередь в статус успешной синхронизации.
